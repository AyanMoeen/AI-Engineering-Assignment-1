1. Problem and scenario

We play a small applied-AI team that has a private text corpus, too small to justify a large foundation model. The practical question from our lead engineer: can a small Transformer trained from scratch learn the next-token structure of a domain corpus well enough to generate coherent text?

To answer it, we built a miniature GPT-style causal language model in PyTorch. Every Transformer component (attention, masking, multi-head split/merge, positional encoding, blocks, LM head, loss, sampling) is written by us. We load no pretrained checkpoint and use no transformers model classes. PyTorch is used only for tensors, autograd, linear layers, LayerNorm, softmax and the optimizer. We trained on Tiny Shakespeare, tested the architecture, ran ablations, and deployed the model behind a FastAPI service.

Short answer: it learns the surface structure of Shakespeare very well (speaker labels, line breaks, archaic vocabulary, punctuation), but it does not produce coherent meaning. Sections 6 and 8 show the evidence.

2. Transformer foundations

2.1 Why Transformers: sequential vs parallel depth

A recurrent network (RNN/LSTM) processes a sequence of length T one step at a time, so its sequential depth is O(T): step t cannot start before step t-1 finishes. Self-attention connects every position to every other position in a single operation, so its sequential depth is O(1) and all positions can be computed in parallel. The price is memory: attention stores a T x T score matrix per head, so memory grows as O(T^2).

We measured both sides on a GPU (batch 16, d_model 128, forward + backward):

Figure C: LSTM vs attention at different sequence lengths (measured).

Observation: at these tiny sizes the two run at similar speed (for example T=128: LSTM 0.0027 s vs attention 0.0035 s; T=512: 0.0095 s vs 0.0098 s). Attention score memory grows exactly 4x per doubling of T (1 MB, 4 MB, 16 MB, 64 MB). Interpretation: the speed benefit of attention comes from parallel depth, which matters most for long sequences and large models. On a small GPU workload with a highly optimized cuDNN LSTM, we did not see a speed win, so we report the O(1) vs O(T) depth as a theoretical advantage and the O(T^2) memory as a confirmed cost.

2.2 Scaled dot-product attention

Each token produces a query Q, key K and value V vector. The score between two tokens is the dot product of a query and a key. Dividing by sqrt(d_k) keeps the scores from growing with dimension, which would push softmax into a saturated region with tiny gradients. M is the mask: 0 where attention is allowed and minus infinity where it is forbidden.

2.3 Hand calculation (3 tokens, d_k = d_v = 2)

What changes with the mask: without it, token 1 mixes information from all three tokens (output [3.00, 4.00]). With it, token 1 can only see itself, so its output is exactly its own value vector [1, 2]. Token 2 now mixes only tokens 1 and 2 (output changes from [3.41, 4.41] to [2.34, 3.34]). Token 3 is the last token and already sees everything, so its output does not change. Each row of the weight matrix still sums to 1; the forbidden positions get weight exactly 0.

2.4 Multi-head attention and tensor shapes

With d_model = 256 and 4 heads, each head works in a d_head = 64 subspace. The input is projected to Q, K, V of shape (B, T, 256), split into (B, 4, T, 64), attended per head, then concatenated back to (B, T, 256) and passed through an output projection W_o. Split and merge are explicit reshape/transpose operations in src/attention.py. The trace below uses a small config (d_model 32, 4 heads, T 6) so the numbers are easy to read:

2.5 Positional encoding

Attention itself has no notion of order: shuffling the tokens would only shuffle the outputs. We therefore add a fixed sinusoidal encoding to the token embeddings:

Low dimensions oscillate quickly and high dimensions slowly, so every position gets a unique, smoothly varying signature, and the encoding has no trainable parameters.

2.6 The Transformer block

We use a pre-LayerNorm decoder block with residual connections around both sublayers:

Residual paths let gradients flow directly through the stack, and LayerNorm keeps activations well scaled. Four blocks are followed by a final LayerNorm and a linear LM head from 256 dimensions to the 65-character vocabulary.

2.7 BERT (bidirectional) vs GPT (causal)

BERT is trained with masked language modeling: some tokens are hidden and predicted using context on both sides, so its attention matrix is full. GPT is trained to predict the next token. If a position could see the future, it could simply copy the answer, so the attention matrix must be lower-triangular, both in training and in generation.

We ran a small comparison experiment: change only the last token of the input and measure how much the output at position 0 changes.

The causal result is exactly zero, which is the behavior our unit test test_mask.py checks for the full model.

3. Implementation

The repository layout is: src/tokenizer.py (character tokenizer), dataset.py (contiguous windows with shifted targets), attention.py (scaled dot-product and multi-head attention), positional_encoding.py (sinusoidal, plus a learned variant for experiments), transformer_block.py, gpt.py (full model), train.py, generate.py (CLI sampling) and api.py (FastAPI). Experiments live in experiments/ and tests in tests/.

  • Tokenizer: character-level, deterministic, vocabulary of 65 symbols made of every unique character in the corpus, sorted (letters, punctuation, space and newline). There are no special tokens: the model is trained on a continuous stream of characters, and generation simply continues the prompt.
  • Loss: for a window of T+1 characters, the input is characters [0..T-1] and the target is characters [1..T], so the target at position t is the next character after the input at position t. We use token-level cross-entropy over the 65 logits at every position.
  • Generation: autoregressive loop. At each step we take the logits of the last position, divide by a temperature, optionally keep only the top-k logits, apply softmax, sample one character, append it, and repeat. The context is cropped to the last 128 characters.
  • Training loop: AdamW, linear warm-up for 100 steps then cosine decay from 3e-4 to 3e-5, gradient clipping at 1.0, evaluation on 50 batches every 250 steps, and a generated sample printed every 1000 steps. All settings are in configs/tiny_gpt.yaml.

4. Dataset and preprocessing

We used the Tiny Shakespeare corpus (about 1.1 MB, roughly 40,000 lines of Shakespeare, downloaded from the char-rnn repository by Andrej Karpathy). The text is used as is, with no filtering. The last 10% of the character stream is held out for validation (val_fraction = 0.1), and training windows are sampled as random contiguous slices of 128+1 characters. The vocabulary has 65 characters.

5. Training setup

We trained on a Google Colab T4 GPU. One batch is 64 sequences x 128 characters = 8,192 tokens, so 5,000 steps process about 41 million tokens. With a training split of roughly 1 million characters, this is about 40 passes over the data, which matters for the generalization gap discussed below.

Observation: all four heads are strictly lower-triangular, as the causal mask requires. Most heads place large weight on the diagonal band, meaning the previous few characters. 7. Ablation study

We ran three controlled experiments, changing one factor at a time from the base configuration (4 layers, 4 heads, context 128). To keep runs cheap, each ablation used 2,000 steps, so the base value (val loss 1.7150) is higher than the fully trained model (1.5052 at 5,000 steps). All ablations use the same seed (1337) and a single run per setting.

Table 3: ablation results.

Figure 9: ablation plot (validation loss, time and memory).

Depth: 2 vs 4 vs 6 layers

Observation: validation loss improved from 1.8202 (2 layers) to 1.7150 (4) to 1.6819 (6), with parameters 1.6M, 3.2M and 4.8M and training time 87.5, 166.2 and 245.2 s. The first doubling gave an improvement of 0.105, the next step only 0.033, while cost kept growing roughly linearly.

Interpretation: extra depth helps, plausibly because more layers allow more rounds of mixing context, but returns diminish quickly at this data size. Four layers is a reasonable cost/quality compromise; six layers is the best model measured but costs about 48% more time than four for a small gain.

Heads: 2 vs 4 vs 8

Observation: validation loss was 1.7258, 1.7150 and 1.7257. Parameter count is identical (3,192,832) in all three, because the head count only changes how the 256 dimensions are split. Time rose from 157.5 to 165.7 to 186.5 s and peak memory from 740 to 806 to 950 MB. Generation quality looked similar across all three (see outputs/samples/ablation_samples.txt).

Interpretation: at this scale head count barely matters for loss; the 0.011 difference is small and with a single seed we cannot separate it from run-to-run noise. More heads only added cost, because each head gets smaller (d_head 128, 64, 32) and more attention matrices are materialized. We therefore keep 4 heads.

Context length: 64 vs 128 vs 256

Observation: validation loss was 1.7504, 1.7150 and 1.7081, while training time was 83.1, 166.1 and 362.3 s, and peak memory 401, 806 and 1821 MB. Throughput stayed near 98.6k tokens/s for 64 and 128 and dropped to 90.4k tokens/s at 256.

Interpretation: a longer context helps, with a large gain from 64 to 128 and a small one from 128 to 256. Memory grows faster than linearly, consistent with the O(T^2) attention matrices from Section 2.1, so doubling context to 256 roughly doubled time and more than doubled memory for a 0.007 improvement. Because the batch size is fixed at 64 sequences, longer contexts also see more tokens per step, so part of the gain may come from extra data per step and not from long-range modeling alone.

8. Failure analysis

Failure 1: repetition loops under greedy decoding. Greedy decoding on "ROMEO:" falls into the loop "And the season of the season of the seasons" and never leaves it (distinct 4-grams 0.31). Likely cause: always taking the highest-probability character makes a repeated phrase self-reinforcing, since its own repetition keeps the most likely continuation inside the pattern. Temperature plus top-k sampling avoids it, which is why we use T=0.8, top-k=40 as the default.

Failure 2: invented words and incoherent meaning. Samples contain non-words ("orason", "kedgess", "fush substing") and speakers who answer with unrelated sentences. Likely causes: (a) character-level modeling forces the model to learn spelling from scratch, and a small mistake at any character yields a non-word; (b) only 3M parameters and about 1M training characters; (c) a context of 128 characters is roughly two lines of verse, so the model cannot track plot or topic across a scene.

Failure 3: train/validation gap. Training loss 1.28 vs validation 1.51 shows partial memorization after about 40 epochs. Dropout 0.1 and weight decay 0.01 limit it but do not remove it; more data or stronger regularization would be needed to close it.

10. Conclusion

A Transformer written from scratch with about 3.2 million parameters trained for roughly 7.5 minutes on a single T4 GPU learns the form and local statistics of Shakespeare: validation perplexity 4.5 over 65 characters, correct play formatting, and mostly real words. It does not learn meaning, and the samples show it.

Our experiments support three conclusions. (1) The causal mask is what makes next-token training valid: with it, changing future tokens has zero effect on earlier positions, and without it the output moves. (2) Within this small regime, depth and context length improve validation loss with diminishing returns while cost grows (linearly with depth, faster than linearly with context), and head count has no clear effect on loss. (3) Decoding matters as much as the model: greedy decoding collapses into repetition, while temperature sampling gives diverse text. Limitations to keep in mind: single-seed ablations, 2,000-step ablation runs, a character-level tokenizer, and generated text that is an experimental artifact and not reliable in any factual sense.
